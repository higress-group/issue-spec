# 中文文案约定

中文界面采用“操作求准，叙事求静”的两层写法。

- 导航、按钮、状态和错误信息使用清楚的现代中文，不让文气妨碍判断与操作。
- 登录、总览、账户页的主标题可以凝练、留白，但含义必须与页面职责相合。
- 叙事页标题引用古籍原句，并在本文件中注明出处。
- 标题之外的说明、步骤和操作文案使用现代白话，不仿写古文。

## 核心术语

| English | 中文 | 说明 |
| --- | --- | --- |
| issue | 议题 | 比“问题”更能容纳提案、任务与讨论。 |
| change | 变更 | 与工程语境一致，不译作“改变”。 |
| proposal | 提议 | 强调尚待讨论和确认。 |
| design | 设计 | 保留工程含义。 |
| implementation | 实施 | 指把设计落到代码与交付。 |
| workflow | 工作流 / 流转 | 功能名用“工作流”，叙事文案可用“流转”。 |
| evidence | 证据 | 指可核验的实现、评审与交付记录。 |
| credential | 凭据 | 与 evidence 的“证据”严格区分。 |
| authority | 权限 | 用户界面优先用熟悉的词，不用“权柄”。 |
| control room | 工作流中枢 | 品牌副标题克制、明确，不使用生造词。 |
| repository | 仓库 | 指承载议题和工作流的容器；不译作“代码仓库”，避免误以为系统托管源代码。 |
| administration | 管理后台 | 比“系统治理”更直接，适合导航和操作页面。 |
| member | 组织成员 | 表示组织级身份，不与仓库级协作者混用。 |
| collaborator | 仓库协作者 | 表示对单个仓库的额外授权。 |
| service account | 服务账号 | 指组织持有的非人员身份。 |
| managed access token / PAT | 托管访问令牌 | 标题和操作文案使用完整中文；需要解释协议时可保留 PAT。 |
| source binding | 源仓库绑定 | 表示本地工作流仓库与外部代码托管仓库身份之间的绑定。 |
| contribution policy | 参与策略 | 表示哪些用户可以参与议题操作，不译作含义模糊的“贡献政策”。 |
| issue desk | 议题工作台 | 聚合议题列表、讨论和权限信息；不译作“问题台”。 |
| change control | 变更工作台 | 作为变更域入口名称；不直译作“变更控制”。 |
| current projection | 当前汇总 | 表示服务端按权限与工作流记录生成的当前视图，避免使用技术味过重的“投影”。 |
| artifact chain | 产物链 | 表示提议、设计和实施产物之间的顺序关系。 |
| projection diagnostics | 结构诊断 | 聚焦工作流记录的缺失、冲突和绑定异常。 |

## 叙事文案

| 页面 | 中文标题 | 中文说明 |
| --- | --- | --- |
| 登录 | 慎终如始，则无败事。 | 把一次变更从提议推进到实现和验证，所有讨论、评审和决定都有清晰记录。 |
| 总览 | 知止而后有定，定而后能静。 | 选择一个组织，确认你拥有的权限，然后继续处理相关工作。 |
| 账户 | 从心所欲，不逾矩。 | 这里会分别显示你的身份来源、权限范围和会话有效期。 |
| 议题 | 切问而近思。 | 选择一个仓库，集中处理议题，让背景、讨论、决定和后续行动留在同一条时间线上。 |
| 变更 | 穷则变，变则通，通则久。 | 在一处查看提议、设计、实施与交付进展，及时识别阻塞和结构异常。 |

出处与页面含义：

- 登录页“慎终如始，则无败事”出自《道德经》第六十四章，用来表达一次变更应当自始至终认真完成。
- 总览页“知止而后有定，定而后能静”出自《礼记·大学》，用来表达先明确目标和所处位置，再从容开始行动。
- 账户页“从心所欲，不逾矩”出自《论语·为政》，用来表达在清楚的身份、权限和会话边界内从容行事；英文标题对应为 “Freedom within clear bounds.”。
- 议题页“切问而近思”出自《论语·子张》，用来表达围绕具体议题认真追问、联系当前工作思考。
- 变更页“穷则变，变则通，通则久”出自《周易·系辞下》，用来表达在约束和阻塞中识别变化、打通路径并形成可持续的交付。

## 覆盖边界

首轮覆盖全局语言切换、登录与首次引导、总览页、主导航、公开仓库外壳、账户页、个人访问令牌以及 404 / 路由错误页。第二轮覆盖管理后台、组织、仓库设置、成员、协作者、服务账号、托管访问令牌、源仓库绑定与 Webhook 投递。第三轮覆盖议题工作台、议题列表与讨论、变更工作台、变更看板与详情、代码变更关联和结构诊断。
